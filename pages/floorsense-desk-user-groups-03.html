Desk & User Groups

Group desks into neighbourhoods, and users into groups, for reporting and policy overrides.

Configure

Desk Group Setup

Often companies will allocate certain groups of workpoints on a floor to belong to a "neighbourhood". Floorsense calls these neighbourhoods "Desk Groups".

Configuring Desk Groups allows for both reporting granularity on reservations and occupancy for a group of desks rather than an entire floor, and also allows for different policy (booking rules) to be applied based on the Desk Group.

To setup Desk Groups we need a marked up floorplan identifying which desks/workpoints belong to which Desk Group, and the names of the Desk Groups to configure.

Please be careful with extra restrictions and policy overrides — they add complexity and can make the system harder to set up and maintain for administrators. Keep overrides as simple as possible.

User Group Setup

User Groups allow for further granularity in setting desk policy (rules) for booking. The policy for a User Group overrides the policy for a Desk Group (or the default policy if no Desk Groups are configured).

A Floorsense user can only belong to a single User Group. Typically the User Group names can be imported from a source system via file upload, and each user record uploaded is tagged with which User Group it belongs to.

Alternatively, User Groups can be configured via the Admin portal and users added to these User Groups after the users themselves have been auto-created/imported via an independent import process.

User Groups cannot be imported automatically for Single Sign-On auto-created users, and also cannot be imported from Active Directory, unless the user only exists in a single group within Active Directory.
