# Smartalock Configuration Studio

A static HTML/CSS/JS prototype for designing, configuring and documenting Smartalock locker system deployments. No build step — open any page directly in a browser, or serve the folder with any static file server.

## Start here

Open `smartalock-templates-00.html` (**Project Registration**) — this is the site's actual starting page, and it now lives at the project **root**, not under `pages/`. It has no back-arrow at all (nothing comes before it, and rather than disabling the arrow it's removed outright). Its Contacts card includes a full-width textarea right after IT Contact — "Please provide the names and email addresses of individuals who require access to the Floorsight Administering Web Portal (1-2 people)" — saved as `project.registration.portalAccess`, autosaving on the same debounce as every other field on this page.

From there the flow is:

1. `smartalock-templates-00.html` (root) — Project Registration
2. `pages/smartalock-it-configuration-02.html` — IT Configuration & Integrations
3. `pages/pick-a-product.html` — the product picker, reached only after 00 → 02, not before

`pages/pick-a-product.html` (formerly `index.html` — renamed and moved into `pages/` since it's no longer the entry point) lets the client choose which product line to configure next (**Smartalock** or **Floorsense**), each with a description, icon and a live-switching preview panel. It also has its own "← Back" link to `smartalock-it-configuration-02.html`, since it's no longer the first page in the flow. Choosing **Smartalock** here resumes the wizard at `smartalock-access-methods-09.html` (skipping 00/02, since those are already done) and continues through the rest of the **10-step configuration wizard** under `pages/`, named `smartalock-<module>-0X.html`:

As with the Smartalock wizard, module numbers don't match click-through order here either: the actual path is **01 → 02 → 03 → 04 → 05 → 06 → 00 → `floorsense-out-of-box-policy.html`** (titled **Configuration Summary**, formerly "Out of the Box Policy" — see below). `floorsense-reservation-types-01.html` is the true entry page (its back-arrow returns to `pick-a-product.html`), then continues through Check-in Methods, Desk & User Groups, Prebooking, Business Hours, and the Optional Features hub — every setting that applies to everyone by default — and finally to Setup Path (module 00), which is no longer a decision point (see below) but a confirmation step whose Continue button leads straight to the Configuration Summary. `floorsense-default-reservation-times-07.html` onward (07–13: Default Reservation Times, Check-in Window, Auto-Release on Idle, Reservation Length, NSNP, FME, Anti Desk Hogging) are **not** part of this enforced click-through path, and — unlike every other reorder in this wizard's history — are also **no longer shown in the progress bar at all**. The progress bar was shortened from 14 segments (the old fixed 00–13 numeric list, shown identically on every page) to exactly 7, now in actual click-through order: Desk Allocation Method, Check-in Methods, Desk & User Groups, Prebooking Window, Business Hours, Optional Features, and Core Complete. All 14 numbered pages carry this same 7-segment bar — the 7 pages actually in the flow show their own segment as `current`; the 7 orphaned pages (07–13) show the identical bar with no segment marked `current`, since none of them are in the list. Those 7 pages are still fully built, functional, and reachable by direct link, but per the client's direction they're meant to be reached only from the Configuration Summary when someone wants to edit a specific setting after the fact, not from the main wizard nav — wiring up those edit entry points from the summary is a separate follow-up task, not yet done. The four optional pages among them (09, 11, 12, 13) still carry their own `NAV_SEQUENCE`/`seqResolve()` skip-logic for when they're reached directly, so their own internal Next/Back still transparently skips whichever of the four is switched off on the Optional Features hub. Its state lives under `project.floorsense.wizard` in the same `configurationProject` localStorage key described below — `setupPath`, `reservationTypes`, `checkinMethods`, `deskUserGroups`, `prebookingAdvance`, `businessHours`, `defaultReservationTimes`, `checkinWindow`, `idleRelease`, `reservationLength`, `nsnp`, `fme` and `antiDeskHogging` respectively; the Optional Features hub (module 06) introduces no state object of its own — its four switches read and write those same existing `idleRelease.enabled`/`nsnp.mode`/`fme.mode`/`antiDeskHogging.mode` fields directly, only recording its own `moduleStatus` entry for the progress bar.

Setup Path (module 00) no longer offers a Relaxed/Pre-Configured/Strict/Build Your Own choice — that entire branching decision was removed once the page moved to the end of the core click-through chain (see the paragraph above and the file's own NOTE for the full history of both changes). It's now a single card-free confirmation screen: a short message confirming the core policy (desk allocation, check-in methods, desk & user groups, prebooking window, business hours, optional features) is configured and applies to everyone by default, plus a note that the Configuration Summary also lets you save the configuration as a General Policy and layer on neighbourhood-specific policies for individual Desk Groups. Its Continue button is the wizard's one remaining path into `floorsense-out-of-box-policy.html`, reached with no `?preset=` query string (that page already defaults to its "recommended" copy when no preset param is present). The progress-bar tooltip for this module was renamed from "Setup Path" to "Core Complete" across all 15 Floorsense pages to match; the underlying `data-module="setup-path"` key is unchanged. `floorsense-out-of-box-policy.html` itself was renamed from "Out of the Box Policy" to **Configuration Summary** in its `<title>`, hero heading, and progress-bar tooltip (filename, `data-module="out-of-box-policy"`, and its `outOfBoxPolicy` state key are unchanged — display text only).

The Configuration Summary also delivers on that "layer on neighbourhood-specific policies" note: a conditional **Additional Policies** section, hidden unless Desk Groups and/or User Groups are actually in use (`project.floorsense.wizard.deskUserGroups.{deskGroups,userGroups}.none === false`). When shown, a "+ Duplicate Core Policy" button lets the client clone the core policy — the same five groups that already carry an Edit pill on this page (Check-in Window, Prebooking & Duration, Check-in Behaviour, Access Methods, and Additional Options/NSNP-sit-stand-recurring-DND) — under a custom name like "Finance" or "CEO," classify it as a **Desk Group Setting** or **User Group Setting** via a two-way pill toggle (whichever type isn't currently in use is disabled), then tweak the clone's own numbers/toggles independently, up to 3 additional policies. An info box next to the section spells out that User Group settings take precedence over Desk Group settings (e.g. a Desk Group capped at 1 desk per user is overridden by 15 for a user who's also in a User Group allowing 15). Each policy starts collapsed, showing only its name (or an italicised "Untitled policy" placeholder), its Desk/User Group badge, and a Remove button — tapping the row expands it to reveal the actual form controls (number inputs, `.policy-switch` on/off toggles ported from the Optional Features hub, a NSNP `<select>`, and checkbox rows for Access Methods); a newly created policy opens expanded automatically, while ones loaded from a saved project start collapsed. Once at least one additional policy exists, the core policy column above shrinks to a denser, secondary-looking layout (reverting the moment the last one is removed), since focus has shifted to the named policies. Whenever Additional Policies is shown at all, it now sits in a second column to the right of the core policy (a two-column grid, core policy ~460px wide on the left, Additional Policies filling the rest) rather than stacking below it; it collapses back to a single column under 860px, and to a single block (core policy alone, re-centred) when neither Desk nor User Groups is in use. Everything autosaves on every change like the rest of the wizard.

The core policy itself is now a single collapsible card rather than six separately-boxed groups: a header bar ("Core Policy" + a "Not yet saved"/"Saved" status pill) is always visible and can be tapped at any time to expand or collapse the card, and a "Save Core Policy" button at the very bottom of the expanded card marks it saved and collapses it in one action. State (`project.floorsense.wizard.corePolicyCard = { saved, collapsed }`) persists independently of the page's own "Confirm & finish" action, so the card reopens or stays tucked away exactly as it was left on a later visit.

Every policy card — core, and each additional Desk Group / User Group policy — also carries a **Maximum Desks Per User** fill-in field (default 1), the same figure already referenced in the precedence-notice example above ("...allows 1 desk per user but a User Group...allows 15"). It's a plain number input, editable up to 20, autosaving independently of "Confirm & finish": on the core card it lives at `project.floorsense.wizard.outOfBoxPolicy.maxDesksPerUser`, and on each additional policy it's part of that policy's own object in `project.floorsense.wizard.additionalPolicies`. State lives at `project.floorsense.wizard.additionalPolicies` — a top-level array of up to 3 objects (each with its own `groupType: 'desk' | 'user'`), independent of the core policy's own (still-hardcoded, non-dynamic) summary text. This is purely additive to the Configuration Summary; it isn't wired into "Confirm & finish," the end-user PDF guide, or any other page's Edit links yet.

`assets/documents/floorsense-desk-booking-guide.pdf` — the end-user guide linked from the Configuration Summary's "Explain this policy to your end users" download card — was updated to add a "One desk at a time, by default" item to its Booking & Check-in section, describing the new Maximum Desks Per User setting in plain English (without getting into the Desk Group/User Group precedence mechanics, which aren't end-user-relevant). Its buildable HTML/CSS source, which hadn't previously been committed anywhere in the repo (only the compiled PDF was tracked, so this update required reconstructing the source from the rendered PDF's text and a rendered-page screenshot), is now saved at `assets/documents/src/floorsense-desk-booking-guide.html` so future content changes don't require that reconstruction again. It's rendered to PDF with [WeasyPrint](https://weasyprint.org/) (`weasyprint floorsense-desk-booking-guide.html floorsense-desk-booking-guide.pdf`, or `python3 -m weasyprint ...` if the `weasyprint` command isn't on PATH) — using CSS `@page` margin boxes (`@bottom-left`/`@bottom-right` with `counter(page)`/`counter(pages)`) for the repeating footer rather than a fixed-position element, and inline SVG icons with `stroke="currentColor"` plus a CSS `color:` rule on the containing element (not `stroke:` directly), per the same WeasyPrint quirk noted before — icons render blank otherwise. A literal `·` character is used in the footer's `content:` string rather than a `\00B7` CSS escape, since a CSS hex escape shorter than 6 digits consumes one trailing whitespace character as its terminator, silently swallowing the space that was meant to follow it.

The core policy's Check-in Behaviour group no longer has an Edit link — it never had dedicated fields to edit anyway — and instead has its own two on/off toggles, on by default: "Second swipe checks out" and "Auto-cancel when checking in elsewhere" (`swipeOutRequired`/`autoCancelOnElsewhere`, matching the field names already used on the additional-policy cards). Both autosave to `project.floorsense.wizard.outOfBoxPolicy` independently of "Confirm & finish".

"Confirm & finish" on the Configuration Summary was renamed **"Save & Email Me Summary"** and no longer just shows link buttons or auto-redirects: it still saves `outOfBoxPolicy`/`floorsense.configured`/`moduleStatus` exactly as before, then opens the client's own email app (via a `mailto:` link addressed to "Your Email" from Project Registration) pre-filled with a plain-text summary of the core policy, the **End User Guides** and **Admin Portal Guide** links, and a note that the end-user PDF guide needs downloading and attaching manually (mailto links can't carry attachments). The plain-text summary is generated by walking the core policy card's own rendered rows, so it always matches whatever's on screen — including any Check-in Behaviour toggle or Maximum Desks Per User value changed before saving — rather than being a separately hand-maintained copy. A confirmation panel names the actual recipient (or explains that "Your Email" was never filled in) and offers a manual "Continue to Project Home" link, same as before.

`smartalock-configuration-summary-08.html` (the Smartalock branch's own, read-only Configuration Summary) got the same treatment. This page previously had no completion action at all — just Print and Download JSON — so it gained a new **"Save & Email Me Summary"** primary button (Download JSON was restyled to a ghost button so there's one clear primary action). Clicking it marks `project.smartalock.configured = true`, saves `moduleStatus.summary = true` (which also marks this page's own progress-bar segment as saved — nothing previously did), builds the same kind of plain-text summary (from this page's own `.summary-group`/`.summary-row` content, all plain label/value pairs here — no toggles or number inputs), and opens a `mailto:` link with that summary plus the same End User Guides link and the Smartalock-specific Admin Portal Guide link ("SMARTALOCK FULL ADMINISTRATION GUIDE" on Notion).

Desk Groups (Neighbourhoods) & User Groups (module 03) — originally inserted between Check-in Methods and Setup Path, and now sitting between Check-in Methods (02) and Prebooking (04) in click-through order since Setup Path moved to the end of the core chain — was, at the time it was added, the newest addition to the main flow (not one of the optional tail-end modules). It covers two independent topics with the same shape: a multi-select checkbox grid (`.group-check-card`, ported from Check-in Methods' `.desk-check-card`) — "not use", "provide a list/floorplan (or spreadsheet, for User Groups)", and "apply different override policy" — where "not use" is mutually exclusive with the other two but those two can combine freely; and a conditional policy textarea that only appears once the "apply different policy" option is ticked. Desk Group Setup defaults to "not use" (no concrete example was supplied for it); User Group Setup defaults to "provide" + "policy" both checked, since the brief supplied a real example override policy ("Only Client Care can book desks in the Client Care area; Only HR can book desks in the HR area"), prefilled into that field. An amber caution notice (ported from Setup Path's `.setup-notice`) originally repeated at the bottom of each column warning that policy overrides complicate setup and maintenance; it was later consolidated into a single notice shown once at the top of the page, and reworded again into plainer, client-facing language once the admin-facing phrasing proved unclear: "You don't need to set up Desk Groups unless you want different booking rules for a specific area. Likewise, extra User Groups are optional — only add them if your policy really needs different rules for different groups of users, as each one adds a bit more setup complexity."

Prebooking (module 03) and Business Hours (module 04) swapped numbers per a later reorder request, so Prebooking now immediately follows Check-in Methods/Setup Path and Business Hours comes right after it. Business Hours is a single-topic page in the same one-card, one-timeline explainer style as Check-in Window: one card with a live diagram driven by a time drum on either side (Opens / Closes), setting the standard business hours used as a default for most users. Default Reservation Times (module 07, formerly 05) and Check-in Window (module 08, formerly 06) were originally one combined page ("Check-in Policy") hosting two numbered sections; they were later split into their own single-topic pages, each built as a single explainer card: an icon + description, a live diagram, and a footer strip with supporting context. Default Reservation Times comes right after Business Hours (and, since the Optional Features hub was inserted, right after that hub too) so its default start time is already saved by the time a user reaches Check-in Window, whose own worked example depends on it. Auto-Release on Idle (module 09, formerly 07) uses the same card pattern but as its own single-topic page too, since it was originally going to be a third numbered section on the combined page before being split out — its card and diagram were later restyled to match Check-in Window's/Default Reservation Times' Apple Clock time-drum look (a single duration drum driving a fixed "Reserved" pin and an enlarged "Released" pin), replacing an earlier static SVG flowchart and inline number field.

NSNP (module 11, formerly 10), appended after Reservation Length, was the wizard's first genuinely optional module: "No Swipe No Power" cuts power to a desk's outlets when it's occupied without a valid badge swipe, and requires NSNP relay units installed at each desk to function. Rather than the single-explainer-card pattern, it uses the same 4-option radio-card grid as Setup Path (`.path-check-grid`/`.path-check-card`) to choose a rollout mode — all desks, a client-supplied list of enabled desks, not using NSNP at all (the default), or a free-text "Other" — plus a supplementary Apple Clock-style "Power grace period" drum diagram (5-to-240-minute range, defaulting to 60 min) that only appears once a non-"none" mode is selected.

Auto-Release on Idle (module 09) was later made the wizard's second optional module, off by default: its explainer card gained an on/off `.switch` control (the same toggle pattern used on `smartalock-kiosk-customisation-07.html`) in the card header, and its `.timeline-card` diagram plus footer are now wrapped in a `.idle-body` element that stays hidden until the switch is turned on — the same show/hide convention (not opacity dimming) used for NSNP's conditional grace-period block. Its progress-bar tooltip now reads "Auto-Release on Idle (Optional)" across all pages, and its state gained a new `enabled` boolean (`project.floorsense.wizard.idleRelease = { enabled, idleHours }`), defaulting to `enabled: false`.

Follow Me Ergonomics (module 12, formerly 11), appended after NSNP, is the wizard's third optional module: it lets end users save and apply a custom sit-stand desk height via the FS mobile app. It reuses NSNP's `.path-check-grid` radio-card pattern but simplified to 3 modes instead of 4 — "All sit-stand desks", "We will provide a list of desk types" (assumed supplied separately, same as NSNP's own list option), and "We will not enable mobile app FME" (the default, off) — with no "Other" option and no supplementary numeric setting, since the brief didn't call for either.

Anti Desk Hogging (module 13, formerly 12), appended after FME, is the wizard's fourth optional module and restricts users from repeatedly booking the same desk, to encourage cross-team interaction. It uses the simplest 2-mode version of the `.path-check-grid` pattern — "We will enable this feature" vs. "We will NOT enable this feature" (the default, off) — and, when enabled, reveals two Apple Clock-style value drums ("Time Window", 1–14 days, default 2; "Number of Same Desk Bookings", 1–7 times, default 1) rather than the rail/pin timeline diagram used elsewhere, since "book the same desk N times in a window" has no natural before/after moment to plot on a timeline. A live summary line mirrors the brief's own example phrasing ("This would allow a user to book the same desk twice every 5 days").

Check-in Methods (module 02) dropped its "Floorsense App at Desk" checkbox option; the prebooking option now sits in that same 2nd-position slot instead of its original 5th position, leaving 4 options in order: Building Access Cards (default), Mobile App or Desktop Browser Prebooking (also default), QR Code, and Wallet Pass. No other page needed updating — `floorsense-checkin-window-08.html`'s footer sentence reads the saved selection dynamically off a label map, so it's unaffected by the option's removal.

The Prebooking card was later marked as a second default-on option alongside Building Access Cards, and its heading/copy were simplified from "Floorsense App or Web Portal Prebooking" (with a trailing "or a kiosk with a swipe card reader" clause) to "Mobile App or Desktop Browser Prebooking," describing pre-booking via the Floorsense mobile app or the my.floorsense.com.au desktop browser portal.

Optional Features (module 06), inserted between Business Hours and Default Reservation Times, is a control hub rather than a feature of its own: a single card listing all four optional modules above (Auto-Release on Idle, NSNP, FME, Anti Desk Hogging) as stacked rows, each with a one-line description and the same `.switch` on/off control used on Auto-Release on Idle's own page, all off by default. It reads and writes the exact same state fields each feature's own page already uses (no duplicate state key), so toggling here and toggling from the feature's own page always agree; switching a feature on for the first time seeds it with a sensible non-off default (`'all'` for NSNP/FME's mode, `'enable'` for Anti Desk Hogging's mode, `true` for Auto-Release's `enabled`) without disturbing any other saved settings on that feature. This hub is also what makes the four optional pages skippable: `floorsense-checkin-window-08.html`, `floorsense-reservation-length-10.html`, `floorsense-nsnp-11.html`, `floorsense-fme-12.html`, and `floorsense-anti-desk-hogging-13.html` each carry a duplicated `NAV_SEQUENCE` array plus a `seqResolve(key, direction)` walker that skips any neighboring optional page whose switch is off, so Next/Back always lands on the nearest enabled (or non-optional) page. The progress bar itself is unaffected — it always shows and links to all 14 modules no matter which switches are on.

`pages/dashboard.html` and `pages/reports.html` both link back to `pages/pick-a-product.html` via a **"Configuration Wizard"** nav item, and their **"Summary"** nav item links to `smartalock-configuration-summary-08.html`.

### Conventions used across the 10 wizard pages

- **Shell markup**: `.page-main` > `.panel-topbar` (`.top-frame` with `.brand` + horizontal `.progress-bar`) + `.panel-intro` (hero title/subtext) → `.panel-scroll` (the actual form content) → `.action-bar` (Reset / Save & continue).
- **Progress bar**: `.progress-seg` per module; `.saved` = previously completed, `.current` = active page, hover shows a tooltip with the module name.
- **Typography**: Inter throughout. Hero titles are 76px/weight 200, forced onto a single line via `white-space: nowrap` + a `width:100vw; left:50%; transform:translateX(-50%)` breakout so long titles don't get clipped by their column.
- **State**: each page reads/writes a single `localStorage` key, `configurationProject`, shaped roughly as:
  ```
  {
    id, created, updated,
    registration: { customer, site, projectName, contact, email, phone, ... },
    smartalock: {
      configured, templates,
      wizard: {
        moduleStatus: { registration: true, it: true, ... },  // drives the progress bar
        it: {...}, accessMethods: { selected: [...], cardAssignMethod, pinAssignMethod }, ...
      }
    },
    floorsense: { configured, templates, wizard: {} }
  }
  ```
  Each page's own section of `wizard` is independent — check the `<script>` block at the bottom of any page for its exact fields.
- **Images/diagrams**: pages with a right-hand visual panel (e.g. IT Configuration's architecture diagram) swap the `<img src>` via JS based on form selections — see `ARCH_VISUAL` in `smartalock-it-configuration-02.html` for the pattern.

## The rest of the site

- `smartalock-templates-00.html` (project root) — the site's actual entry point (see "Start here" above).
- `pages/pick-a-product.html` — the product picker (formerly the root `index.html`; renamed and moved into `pages/` since 00 → 02 now happen before it). It no longer links to Dashboard, Configuration Engine, Implementation Ready, or Reports — those pages predate the product-picker flow and are currently only reachable by opening their file directly (`pages/dashboard.html`, `pages/reports.html`, `pages/smartalock-wizard.html`, `pages/smartalock-templates.html`) or via each other's own top nav.
- `pages/dashboard.html`, `pages/reports.html` — surrounding app shell (predates the wizard work above).

- `assets/`, `css/`, `js/` — shared images/icons, stylesheets and scripts for the pages above. Each of the 10 wizard pages is self-contained (styles and script inlined in the page itself) and doesn't depend on `css/`/`js/`.
- `data/`, `docs/`, `output/` — supporting data files, spec docs, and generated report output; not touched by the wizard work.
